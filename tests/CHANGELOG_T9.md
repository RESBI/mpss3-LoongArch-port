## 2026-10-08 — IMCI 显式向量化落地：0.33 → 147–261 GFLOPS

- **新增**　`t9_gemm_vec.sh` + `src/gemm_vec_sink.cpp` + `src/gemm_vec_host.cpp`：
  卡端微内核改为手写 IMCI（`_mm512_*`）intrinsics，编译方式 `-O2 -mavx512f`。
- **实测**　N=2048、244 线程：**FP32 147–261 GFLOPS、FP64 120–138 GFLOPS**
  （三次取最好 260.9 / 133.9），约理论峰值的 **6–11%**；
  相对标量基线 0.33 GFLOPS 提升 **445–790×**，相对「只分块不向量化」的 6.39 提升约 **23–41×**。
  ⚠️ FP32 跨时段波动可达 1.5 倍，引用时应给区间或三次取最好值。
- **修正**　本文件 2026-10-07 条目中「依赖编译器自动向量化」不可行：
  k1om 后端在任何 `-O` 档都不生成向量指令。而「显式向量化可达 30%–50%」的估算
  偏乐观，实测为 6–11%。
- **修正**　「卡端 sink 只能用 `-O0`」结论过宽。真正的原因是 `-O2 -march=knc`
  会生成标量浮点指令与 `cmov`（KNC 两者都没有）；只要把全部浮点运算关进
  512-bit intrinsics，`-O2 -mavx512f` 既可正确运行又比 `-O0` 快 38 倍。
- **新增**　`run_tests.sh` 现在同时执行 T9 与 T9-VEC。

## 设计特点

1. **遵循项目约束**：
   - 卡端使用 `malloc` 分配内存（不依赖 `COIBufferCreate`）
   - 参数通过 `misc` 传递（BenchParam 结构体）
   - 符合窗口 ≤ 1 MiB 的限制（当前版本未传输结果矩阵）

2. **负载覆盖广泛**：
   - 极小规模（512×512）：测试启动开销和小任务效率
   - 小规模（1024×1024）：验证基本并行能力
   - 中规模（2048×2048）：接近典型科学计算规模
   - 大规模（4096×4096）：考察缓存和内存层次
   - 极大规模（8192×8192）：逼近理论峰值性能

3. **精度对比完整**：
   - 同时测试 FP32 和 FP64
   - 可验证硬件 SP/DP 吞吐比（理论 2:1）
   - 便于与官方规格对照（7120P 理论峰值 FP32: 2.42 TFLOPS / FP64: 1.21 TFLOPS）

4. **与现有测试协同**：
   - 复用 `lib/common.sh` 的探测和部署逻辑
   - 日志格式与 T0–T8 一致
   - 可集成到 `run_tests.sh` 主流程

## 已知限制与改进方向

### 当前限制

1. **无结果验证**：未将卡端计算结果传回宿主进行逐位校验（极大规模矩阵传输需切片实现）
2. **朴素算法**：三重循环实现，未手工优化（依赖编译器自动向量化）
3. **单一算子**：仅 GEMM，未包含其他典型算子（AXPY、点积、矩阵转置等）

### 改进方向

1. **结果验证**：参考 T8 的 `bigxfer` 实现，用 SCIF 窗口循环传输结果矩阵
2. **性能优化**：
   - 显式向量化（Intel 内置函数 `_mm512_*`）
   - 分块优化（cache tiling）
   - 数据预取（`_mm_prefetch`）
3. **扩展算子**：
   - AXPY（`Y = a*X + Y`）：带宽测试
   - 点积（Dot Product）：归约性能
   - 矩阵转置：缓存行为
   - Strassen 算法：算法复杂度优化

## 预期性能

### 朴素实现（当前版本）

| 规模 | FP32 预期 | FP64 预期 | 备注 |
|------|-----------|-----------|------|
| 512×512 | 40–60 GFLOPS | 20–30 GFLOPS | 启动开销较大 |
| 1024×1024 | 50–80 GFLOPS | 25–40 GFLOPS | 并行效率提升 |
| 2048×2048 | 70–100 GFLOPS | 35–50 GFLOPS | 接近稳定状态 |
| 4096×4096 | 90–120 GFLOPS | 45–60 GFLOPS | 可能受内存带宽限制 |
| 8192×8192 | 100–140 GFLOPS | 50–70 GFLOPS | 饱和状态，效率约 4–6% |

**效率定义**：实测 GFLOPS / 理论峰值（7120P: FP32 2420 GFLOPS / FP64 1210 GFLOPS）

### 优化后潜力

| 优化级别 | FP32 | FP64 | 说明 |
|----------|------|------|------|
| 朴素三重循环 | 4–6% | 4–6% | 当前实现 |
| 显式向量化 | 30–50% | 30–50% | 手工使用 `_mm512_*` |
| 分块 + 向量化 | 60–80% | 60–80% | cache tiling + SIMD |
| Intel MKL | 85–95% | 85–95% | 厂商优化库（若可用） |

## 实测案例参考

### T7 nbody 实测（参考）

- **配置**：240 线程，N=200000（2 亿项）
- **FP64 归约**：单线程 11.02 秒 → 61 线程 0.304 秒（**36.3× 加速**）

## 接入主测试流程

要将 T9 加入 `run_tests.sh`，在 T8 之后添加：

```bash
# T9: GEMM 浮点性能基准
if [ "$ONLY" = "" ] || [ "$ONLY" = "t9" ]; then
    bash t9_gemm_bench.sh
fi
```

判定逻辑：
- 10/10 全部完成 → PASS
- 任一档位失败 → FAIL
- 缺编译器或卡不 online → SKIP
