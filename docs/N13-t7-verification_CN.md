# 附录 N13 — T7：这些测试到底验证了什么

本篇的存在，是因为「计算真的被验证了吗」这个问题，答案一度是
**「没有，至少不像表面上那样」**。T7 套件当时有一个与宿主参考实现比对、
逐位一致的校验和检查，一个能量守恒检查，以及干净的内核日志。看上去相当完备。
而它**无法发现一个错了两个数量级、甚至完全缺失的受力定律**。

下面记录这个发现、它的原因，以及替换它的三层验证。

## 1. 实验

T7 卡端内核真正计算的只有一件事——引力加速度：

```
a_i = sum_{j != i} m_j (r_j - r_i) / |r_j - r_i|^3
```

于是把加速度故意弄坏四次，每次只改 `inv_cubed_pd` 一行，各自跑完整的档位 4：

| 变体 | 物理 | GFLOPS | 能量误差 | 宿主参考检查 |
|---|---|---|---|---|
| A | 正确 | 74.09 | 2.999e-05 | **通过**，差 2.96e-16 |
| B | `inv = m·x·0.5` —— 毫无意义 | 159.36 | 2.054e-06 | **通过**，差 1.16e-14 |
| C | `inv = 0` —— **完全没有受力** | 223.55 | 1.192e-06 | **通过**，差 1.58e-14 |
| D | 受力 × 2 | 82.06 | 1.809e-04 | **通过**，差 2.96e-15 |

**把受力整个删掉，每一项检查都通过了**，而且能量误差还*变小*了
（1.19e-06 对 3.00e-05）——因为一个不加速的系统当然平凡地守恒能量。

## 2. 为什么

两个原因叠加，都值得直说。

**动力学不由受力主导。** 在 `dt = 0.002`、4 步的尺度上，粒子主要在做弹道运动：
由初速度产生的位移约 8e-4，而**由加速度产生**的位移要小若干个数量级。
校验和是末态位置的求和，所以受力在其中只是叠在一个大弹道项之上的小修正。

**而且受力本身几乎就是零。** 初始条件原本是带 1% 扰动的规则点阵：

```c
const double jitter = 0.01 * sin(12.9898 * i + 78.233);
x[i] = (ix + 0.5) * inv + jitter * inv;
```

规则点阵按对称性没有净引力——每一个拉力都被另一个抵消。只有那点扰动打破对称性，
所以真实加速度极小，把它换成零几乎不改变任何东西。于是那个校验和比对，
实际上是在验证初始条件和积分记账，对受力的检验只发生在**一个本就极小的量的
第四位小数上**。

**两项检查都没有错；它们回答的是另一个问题，而不是它们看起来回答的那个。**
「校验和一致到 0.000e+00」读起来像「物理是对的」。它的实际含义是
「物理与『对本观测量无关』之间的差距不超过舍入误差」。

这与 [N2](N2-t9-gemm-isa-constraints_CN.md) 警告的是同一种失效模式的另一副面孔：
**一个自洽的验证，并不因此就是一个有判别力的验证。**

## 3. 修法：三层验证

每一层回答另外两层回答不了的问题。

### 第一层 —— 直接测超越函数

`rsqrt_max_rel_err`：在设计范围 `x ∈ [2^-12, 2^4)` 内取 512 个对数均匀样本，
用卡端向量 `rsqrt_pd` 算一遍，再与标量 `1.0/sqrt(x)` 逐点比对。

```
卡上 rsqrt 最大相对误差 : 2.556e-16
```

约 1 ulp。这是验证自造倒数平方根
（[N10](N10-t7-gemm-fp64-no-transcendentals_CN.md)）的唯一办法——校验和无法把
误差定位到某一个函数上，而这个函数恰恰是整套算术里唯一被**发明**而非移植的部分。

### 第二层 —— 受力核与标量参考比对

`accel_max_rel_err`：让向量内核只算前 64 个天体，输出与一个直接用 libm `sqrt`
和 `/` 的朴素标量循环逐点比对——标量循环在**卡上的标量编译单元里**执行。

```
受力核最大相对误差 : 6.340e-16
```

便宜（64² 对）、决定性，而且正是原套件完全缺失的那一层。
把四个坏变体重新拿它跑一遍：

| 变体 | 受力核误差 | 判定 |
|---|---|---|
| A 正确 | 6.340e-16 | 通过 |
| B `inv = m·x·0.5` | **1.001e+00** | **失败** |
| C `inv = 0` | **1.000e+00** | **失败** |
| D 受力 × 2 | **1.000e+00** | **失败** |

**每一个都被抓住。而端到端校验和一个都没抓住。**

**这项自检自己也有个洞，而且是同一个实验发现的。** 最初它只对 64 个天体
（8 个向量块）跑内核，而并行度守卫（[N12](N12-t7-nbody-headroom_CN.md) §3）
判定这些工作项铺不满 240 个线程，于是退回单块尾循环。**两路展开的主循环——
承担几乎全部物理计算的那条——因此从未被执行到。** 症状很明显：
把它*那条*的倒数平方根换成常数，自检仍旧报 6.340e-16，因为它在测别的代码。

内核现在导出 `nbody_accel_force2()` 让自检能强制走两路，并两条都跑：

| | 第二层结果 |
|---|---|
| 正确内核，两条路径 | 6.340e-16，通过 |
| 两路主循环被破坏 | **1.001e+00，失败** |

> **规则。** 一个自己挑选路径抵达代码的单元测试，测的可能不是真正跑的那段代码。
> 要确认测试覆盖的是你在意的那个分支——办法就是把这个分支弄坏，看测试是否发现。

### 第三层 —— 端到端轨迹比对（默认只在小档）

> **范围。** 这一层是最贵的一层——O(N²)·steps——并且**对 N > 16384 默认关闭**：
> 六档全开会把套件从 32 秒拖到 227 秒。`T7_REF=1` 可强制全部开启，
> 而驱动脚本把被跳过的档记为 **SKIP**，绝不记为 PASS。第一、二层**不**可选，
> 任何档位都执行——这是刻意的：它们才是有实际判别力的那两层（§1），
> 而且代价是毫秒级。

宿主参考默认在前三档比对。它是 O(N²) 的，因此做了
并行化——但**只对 `i` 并行**，每个线程跑完整的顺序 `j` 循环，因为那才复现卡端
内核的形状（一条车道顺序累加一个天体的 `j` 循环）。改成对 `j` 并行或做跨线程
归约，求和次序就变了，比对也就失去意义。

```
默认（N <= 16384）： 档位 1 差 0.000e+00 · 档位 2 差 0.000e+00 · 档位 3 差 1.482e-16
T7_REF=1（全部六档）：档位 4 差 2.960e-16 · 档位 5 差 2.963e-16 · 档位 6 差 1.481e-16
```

六档强制全验证跑出 19/19 通过、227 秒；默认跑出 16 通过 + 3 跳过、32 秒。
**被跳过的检查就报成跳过，不报成通过**——§1 的全部要点正在于：
没有跑过的检查不能算作证据。

### 以及初始条件

规则点阵换成了整数散列：

```c
static double hash01(unsigned k)
{
    k = (k ^ 61u) ^ (k >> 16);
    k *= 9u;
    k = k ^ (k >> 4);
    k *= 0x27d4eb2du;
    k = k ^ (k >> 15);
    return (double)(k & 0xFFFFFFu) * (1.0 / 16777216.0);
}
```

两条性质要紧。它是**不规则的**，净引力不再被对称性抵消，动力学真正依赖受力定律。
同时它是**卡端与宿主逐位可复现的**——整数运算加一次乘精确的 2 的幂——
而 `sin`/`cos` 不是，那依赖两边的 libm。

速度仍然用 `sin`/`cos`，也仍然对得上；那是这套工具链组合的性质，
但对于位置，散列把这个疑问直接消掉了。

## 4. 这对报告出来的数字意味着什么

旧的说法「校验和逐位一致」是真的，但作为证据比它看起来弱得多。
新套件报告 **17 项检查**，其中三层是彼此独立的正确性验证：

| | |
|---|---|
| 与宿主参考比对的档位数 | 5 / 5 |
| `rsqrt` 最大相对误差 | 2.556e-16 |
| 受力核最大相对误差 | 6.340e-16 |
| 内核异常 | 0 |

性能数字也在改正后的初始条件上重测过，是与标量 `-O0` 构建**在同一份输入上**、
双方都通过参考检查的对比——见 [N9](N9-t7-nbody-overview_CN.md) §1。
加速比此前报告的要大（N=65536 时 31.6×），因为受力主导的负载对标量那条
libm `sqrt` 加除法的路径惩罚更重，而这正是诚实的对比。

## 5. 规则

> **测试通过，证明的是「代码与测试自洽」，不是「测试有能力失败」。**
> 在信任一个数值检查之前，先把它本该保护的东西弄坏，确认这个检查能发现。
> 这里，故意删掉整个引力，所有既有检查依然全绿。

> **自己发明的部件，要单独、直接地验证。** 在一个混沌系统上做端到端比对，
> 是好的集成测试、糟糕的单元测试：它说不清*哪个*部件错了，而且——正如本例
> ——它可能对某个部件根本没有灵敏度。超越函数用 512 点扫描、受力核用 64 体
> 比对，代价是毫秒级，结论是决定性的。

> **检查负载是否真的锻炼了被测代码。** 一个主导项与答案无关的基准，
> 会用错误的理由报出正确的数字。点阵初始条件让受力成为观测量的第四位小数修正；
> 散列让它成为观测量本身。
