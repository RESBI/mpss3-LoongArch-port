# 附录 N4 — T9 GEMM 步骤 2：消除固定并行开销

**实测效果：FP32 57.4 → 104.1 GFLOPS，FP64 45.4 → 61.1 GFLOPS**
（N=2048，244 线程）。微内核一行未改，工作全在它外面的测量装置上。

## 1. 症状：一个不该存在的常数项

用 [N3](N3-t9-gemm-explicit-vectorisation_CN.md) 的向量化内核测三个规模。
如果内核是唯一成本，时间应当按 N³ 增长 —— 从 N=256 到 N=2048 工作量差 512 倍。

| N | 工作量（GFLOP） | 耗时（s） | 折算 GFLOPS |
|---|---|---|---|
| 256 | 0.0336 | 0.152 | 0.22 |
| 1024 | 2.147 | 0.198 | 10.85 |
| 2048 | 17.18 | 0.299 | 57.43 |

工作量涨 512 倍，时间只涨 2 倍。用后两点拟合：边际速率 ≈ 125 GFLOPS，
**固定成本 ≈ 0.15 s**。N=2048 时它占去一半运行时间；N=256 时几乎就是全部。
内核从来没有基准说的那么慢 —— 是基准在测进程启动。

## 2. 原因一：OpenMP 线程场是在计时区间内创建的

`omp_set_num_threads(240)` 之后的第一个 `omp parallel for` 会惰性地在进入时创建
线程场。在这张卡上、244 个硬件线程的情况下，这个创建过程（线程派生、栈分配、
亲和性设置、首次屏障）代价在 100 ms 量级 —— 从保留的冷/热两列里直接可见：

```
卡端耗时   : 0.138459 s  (热)
冷启动对比 : 0.258473 s  (线程场创建等一次性开销 120.0 ms)
```

**修法。** 先**不计时**跑一遍内核，再对第二遍同样的跑法计时并上报。
这里它成立有个前提：微内核是覆写 C 而不是累加进 C
（[N3 §2.2](N3-t9-gemm-explicit-vectorisation_CN.md)），所以第二遍幂等、
产出同样的 C。结果结构体同时带两个数（`time_us` 与 `time_us_cold`），
让固定成本继续可见而不是被悄悄藏掉 —— 它是真实存在的，只是不属于内核的成本。

## 3. 原因二：`schedule(dynamic,1)` 铺在 16384 次迭代上

并行循环是 `collapse(2)` 铺在 `(j条带, i行块)` 上。N=2048、`MR32=8` 时是
`(2048/16) × (2048/8) = 128 × 256 = 32768` 个微内核，而 `dynamic, 1`
意味着每一个都要去抢**同一个共享计数器**。244 个线程锤一个原子变量、锤 32768 次，
纯属争抢 —— 而且什么也没换来，因为微内核代价均匀、根本没有负载需要平衡。

**修法。** 改成 `schedule(static)`。迭代被一次性均分成等长连续区段，
每个线程走自己那段连续区间，顺带还更利于缓存（连续的 `i0` 块复用同一条 B 条带
—— 见 [N5](N5-t9-gemm-b-panel-packing_CN.md)）。

## 4. 结果

| | 改前 | 改后 |
|---|---|---|
| FP32 GFLOPS，N=2048 | 57.4 | **104.1** |
| FP64 GFLOPS，N=2048 | 45.4 | **61.1** |
| FP32 GFLOPS，N=1024 | 10.85 | **47.84** |
| FP32 GFLOPS，N=256 | 0.22 | **1.68** |

N=1024 在完全不碰内核的改动上拿到 4.4 倍，这是"此前的数字由测量装置主导"的
最清楚证据。固定成本从约 0.15 s 降到约 28 ms。

同一次扫描还留下两条次要观察，保留下来是因为它们界定了"多少工作量才算够"：

- **N=2048 时 244 线程是合适的工作点**，但往下并非线性。实测每线程速率：
  1 线程 1.34 GFLOPS，4 线程（= 一个核）5.40，60 线程 75.8，120 线程 99.8，
  240 线程 124.1。60 → 240 这一档（线程 ×4、核 ×61）只买到 1.6 倍，
  这是内核受**访存延迟**而非发射限制的第一次暗示 —— 下一节就沿这条线走。
- **剩余那约 28 ms 不值得继续追。** 它是每次 offload 调用的一次性开销；
  真实负载会在多次调用间把它摊掉。

## 5. 规则

> 调内核之前，先用至少三个规模拟合"时间对工作量"，量出固定成本。
> 在这个平台上一次 offload 调用带着约 0.1 s 的线程场创建开销，
> 所以总运行时间与之相当的基准测的是测量装置。可以做免计时预热 ——
> 但仅当内核幂等，并且要把冷启动数字一并上报。
> 工作量均匀时优先 `schedule(static)`；几百线程下的 `dynamic,1`
> 是纯粹争抢，没有补偿性收益。
