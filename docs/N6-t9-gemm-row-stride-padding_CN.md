# 附录 N6 — T9 GEMM 步骤 4：A 行距填充

**实测效果：FP32 113.9 → 149.2 GFLOPS，单核 FP32 5.40 → 16.34 GFLOPS（3.0×）**
—— 本系列单项收益最大、也最反直觉的一步。改动是每行加 64 字节填充。

## 1. 引出它的那个观察

到这一步内层循环已经是教科书形态
（[N3](N3-t9-gemm-explicit-vectorisation_CN.md)），固定开销也没了
（[N4](N4-t9-gemm-fixed-overhead_CN.md)），但从容忍值反推仍然是
**单线程每次 k 迭代约 473 个周期**，而发射上界约 21。循环里只有 42 条指令，
也没有长依赖链。

一次线程扫描把问题的形状摊开了：

| 线程 | GFLOPS | 每线程 |
|---|---|---|
| 1 | 1.34 | 1.34 |
| 2 | 2.69 | 1.35 |
| 4 | 5.40 | 1.35 |
| 60 | 75.82 | 1.26 |
| 120 | 99.80 | 0.83 |
| 240 | 124.08 | 0.52 |

从 1 到 4 线程的完美线性是**延迟受限**的标志：KNC 每核 4 个硬件线程，
它们合起来刚好把单线程所等待的东西喂满。这一点确立之后，问题就变成
*它在等什么* —— 而 473 个周期、只有 17 次载入，答案不在循环里。

## 2. 算术

`A` 是行主序，`lda = N`。微内核同时持有 A 的 `MR` 行，每个 k 步访问
`A[i0+r][k]`（r = 0..MR-1）。行距的字节数是 `N × 4`，N=2048 时正好

```
8192 字节 = 2^13
```

Knights Corner 的 L1 是 32 KiB、8 路、64 字节 line —— 也就是 **64 个组**，
组索引是地址位 **6..11**。步长 2^13 不改变位 6..11。于是这 `MR` 行
**全部映射到同一个 L1 组**：

```
第 0 行:  base + 0·8192   → 组 (base >> 6) & 63
第 1 行:  base + 1·8192   → 组 (base >> 6) & 63     ← 相同
第 2 行:  base + 2·8192   → 组 (base >> 6) & 63     ← 相同
...
```

8 路装不下 16 行。每个 k 步都在驱逐并重取，微内核设计时所假设的
"16 行常驻 L1" 根本不成立 —— 载入落到 L2，而那个延迟是顺序核盖不住的。

这是教科书式的 2 的幂步长病态，而且它在源码里**完全看不出来**：
`lda = N` 是最自然的写法，而且它是对的。

## 3. 修法

给 A 一个带填充的行距 `lda = N + PAD`，`PAD` 取成使步长不再是组索引字段的倍数：

```c
#define PAD32 16    /* float ：每行 +64 字节 */
#define PAD64 8     /* double：每行 +64 字节 */
```

FP32 的步长变成 `(2048 + 16) × 4 = 8256` 字节 `= 64 × 129`。
相邻行的组索引相差 `129 mod 64 = 1`，于是 16 行落在 16 个不同的组。
FP64 是 `(2048 + 8) × 8 = 16448 = 64 × 257`，同样安全。

**填充不改变逻辑数据。** `A[i][k]` 的值不变，填充字节内核根本不读。
这一点很重要，因为宿主参考实现独立计算同一个矩阵 —— 宿主侧一行都不用改，
校验和比对在改动前后都成立。

分配与断言：

```c
const uint32_t lda = N + PAD32;
float *A = (float *)_mm_malloc((size_t)N * lda * sizeof(float), 64);
```

## 4. 结果

| | 改前 | 改后 |
|---|---|---|
| FP32，N=2048 | 113.9 | **149.2** |
| 单核 FP32（4 线程） | 5.40 | **16.34** |
| 每次 k 迭代周期数（1 线程） | ~473 | ~157 |

应当引用的是**单核**数字，因为它把线程数与并行装置的影响隔离掉了：
单核 **3.0×**。

同一次扫描里 FP64 只从 61.1 走到 68.1 —— 不是因为填充对它无效
（FP64 的步长也填充了），而是 FP64 的最优寄存器块不同，那是
[N7](N7-t9-gemm-jblocking-and-tuning_CN.md) 的内容。走完那一步之后 FP64 到 133.9。

## 5. 规则

> 只要同时持有矩阵的多行（或多列），就检查行距是不是 2 的幂、
> 以及那个幂是否落在 L1 组索引字段里。如果是，所有行都别名到同一个组，
> 相联度被白白浪费。把步长填充一条 cache line 是两个字符的修复，
> 却可能让吞吐翻三倍 —— 而且它不扰动逻辑值，参考实现无需改动。
>
> 这条要从**单核**测量里推出来，不能从多线程里推：延迟受限的内核会从
> 1 线程线性扩展到"每核硬件线程数"，然后变平。是那个特征 ——
> 而不是一个绝对值偏低的数字 —— 区分了"在等存储"和"发射槽用完了"。
