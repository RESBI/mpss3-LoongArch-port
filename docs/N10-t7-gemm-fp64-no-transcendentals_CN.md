# 附录 N10 — T7：KNC 没有 FP64 超越函数，那就自己造一个

T7 优化的成败全在这一步。N 体内核需要 `1/sqrt(r²)`——每对粒子一次，而粒子对
就是全部工作量。在任何普通 x86 上都有对应指令；**在 Knights Corner 上，
对 double 而言没有。** 替代品只能手工拼装。

## 1. 手册说缺什么

方法：把 *Phi ISA Reference Manual* 抽成文本，取其指令索引（164 条），按后缀筛选。

**所有带 `PD` 后缀的 FP64 向量指令：**

| 存在 | 不存在 |
|---|---|
| `VADDPD`、`VADDNPD`、`VSUBPD`、`VSUBRPD`、`VMULPD`、`VFMADD*PD`、`VGMAXPD`、`VGMINPD` | **`VSQRTPD`** |
| `VCMPPD`、`VBLENDMPD`、`VPCMPD`、`VFIXUPNANPD` | **`VDIVPD`** |
| `VMOVAPD`、`VLOADUNPACK*PD`、`VPACKSTORE*PD`、`VGATHERDPD`、`VSCATTERDPD` | **`VRSQRTPD`**（任何修订版都没有） |
| `VCVTDQ2PD`、`VCVTPS2PD`、`VCVTUDQ2PD` | **`VRCPPD`**（任何修订版都没有） |
| **`VGETEXPPD`、`VGETMANTPD`** —— 取指数 / 取尾数 | **`VEXPPD`、`VLOGPD`** |
| `VRNDFXPNTPD` —— 舍入 | `VCVTPD2PS`、`VCVTPD2DQ`（降精度转换） |

FP32 侧**是有的**：`VRSQRT23PS`、`VRCP23PS`、`VEXP223PS`、`VLOG2PS`。
注意命名——是 **"23" 而不是后续修订版的 "28"**：最初搜 `VRSQRT28PD` 一无所获，
而汇编器与手册一致：接受 `vrsqrt23ps`、拒绝 `vrsqrt28ps`。

也就是说 KNC 的 FP64 流水线只有乘、加、FMA、比较，以及指数/尾数提取，
别的没有。`double` 的 `sqrt()` 与 `/` 会编译成库调用。

## 2. 工具链又加了什么

intrinsic 在工具链头文件里有声明，但「有声明」不等于「能用」。编译加反汇编探测
（`-O2 -mavx512f -mavx512er`）：

| intrinsic | 结果 |
|---|---|
| `_mm512_sqrt_pd`、`_mm512_div_pd` | **汇编报错** —— `vsqrtpd` / `vdivpd` "not supported on k1om" |
| `_mm512_rsqrt28_round_pd`、`_mm512_rcp28_round_pd` | 汇编报错 —— `no such instruction: vrsqrt28pd` |
| `_mm512_rsqrt14_pd`、`_mm512_rcp14_pd` | 汇编报错 —— `no such instruction: vrsqrt14pd` |
| `_mm512_cvtpd_epi32` | 汇编报错 —— GCC 生成 `vcvtpd2dq`，KNC 叫 `VCVTFXPNTPD2DQ` |
| `_mm512_roundscale_pd` | 汇编报错 —— GCC 生成 `vrndscalepd`，KNC 叫 `VRNDFXPNTPD` |
| `_mm512_cvtpd_ps` / `_mm512_cvtps_pd` | 不可用 —— 降精度转换返回 `__m256`，而 KNC 没有 ymm |
| **`_mm512_getexp_pd`、`_mm512_getmant_pd`** | **可用** —— `vgetexppd` / `vgetmantpd` |
| `_mm512_cmp_pd_mask`、`_mm512_mask_mul_pd`、`_mm512_mask_sub_pd`、`_mm512_fmadd_pd`、`_mm512_fnmadd_pd` | 可用 |

注意失败里的规律：**GCC 把其中几条指令按 AVX-512 命名，而 k1om 汇编器只认 KNC
的名字。** 这是工具链缺口而非硬件缺口——但既然拼不出这条指令，缺口就是缺口。

有两个后果值得分开说：

- FP32 的 `vrsqrt23ps` **确实能被汇编器接受**。那么自然而然的计划——把 `r²` 降
  到 FP32、用硬件倒数平方根、再回 FP64 精修——唯一的拦路石就是缺降精度转换。
  两条可用路径（`_mm512_cvtpd_ps` 与 `_mm512_cvtpd_epi32`）都在上表失败了。
  这是整个工作里唯一一处少量内联汇编可能还有价值的地方。
- 而**软件**实现 FP64 `1/sqrt` 所需的东西全都在：取指数、取尾数、FMA、
  掩码乘/掩码减、比较。

## 3. 用手上剩下的东西造 `1/sqrt(x)`

`x = m · 2^e`，`m ∈ [1,2)`，于是

```
1/sqrt(x) = q^e · m^(-1/2)        q = 1/sqrt(2) = 2^(-1/2)
```

两个互相独立的子问题。

### 3.1 整数指数的 `q^e` —— 且不能做整数转换

障碍不在算术，而在于 `e` 是以 **double** 形式拿到的，而 KNC 没有任何汇编器
接受的 double→int 转换，所以常见的位操作套路全部不可用。绕开的办法是**直接对
数值做比较**：因为 `r² ≥ soft2 = 1e-3`，指数满足 `e ∈ [-10, 1]`，于是

```
k = e + 12          ∈ [0, 15]        （覆盖 e ∈ [-12, 3]，即 r² ∈ [2.4e-4, 16)）

r = 1
若 k >= 8 则 r *= q^8,  k -= 8;      q^8 = 2^-4
若 k >= 4 则 r *= q^4,  k -= 4;      q^4 = 2^-2
若 k >= 2 则 r *= q^2,  k -= 2;      q^2 = 2^-1
若 k >= 1 则 r *= q^1,  k -= 1;      q^1 = 2^-0.5
```

四步二进制分解，**全无分支**：每一步变成「比较出掩码 + 掩码乘 + 掩码减」，
共 12 条向量指令，无分支、无整数转换。得到的 `r = q^(e+12)`，常数 `2^6` 折进
下面的多项式以抵消 `q^12`。

### 3.2 `m^(-1/2)` —— 5 次极小极大多项式

在 `m ∈ [1,2)` 上按相对误差加权拟合，然后用 10⁶ 点的网格**独立于拟合代码**
验证（第一次验证用错了变量，竟然「证明」出 100% 误差——这五分钟值得花）：

| 次数 | 最大相对误差 |
|---|---|
| 3 | 4.80e-04 |
| 4 | 7.41e-05 |
| **5** | **1.17e-05** |
| 6 | 1.86e-06 |

取 5 次，系数预先乘 64：

```
p = ((((b5·m + b4)·m + b3)·m + b2)·m + b1)·m + b0
    b0 =  1.458420823144776079e+02     b3 = -6.957543232001837907e+01
    b1 = -1.706815358164975293e+02     b4 =  1.833312835738097135e+01
    b2 =  1.420908449938614524e+02     b5 = -2.009833734602153754e+00
```

### 3.3 两次牛顿迭代

`y ← y · (1.5 − 0.5·x·y²)`，把 `0.5x` 提到循环外后每次三条指令。最坏情况收敛
（`ε' = 1.5ε²`）：

```
种子 1.17e-05  ->  2.04e-10  ->  6.24e-20
```

两次迭代就压到 double 精度以下，结果正确舍入到约 1 ulp——这正是 T7 的校验和
至今仍与宿主基于 libm 的参考**逐位一致**的原因。

### 3.4 总成本

`getexp` + `getmant` + 12（指数缩放）+ 5 条 FMA（多项式）+ 1 乘（合并）
+ 9（两次牛顿迭代）≈ **每 8 对约 30 条向量指令**，而它取代的是每对约 285
个周期的软件 `sqrt` 与除法。

## 4. 这个函数里的两个编译器陷阱

两个都花掉一轮调试，且都与算法无关。

**陷阱 1 —— `(double)EXP_OFF`。** 把指数偏移写成整数强制转换，会让 GCC 生成
`vcvtsi2sd`——标量 int→double 转换，也就是 xmm 指令。必须写成字面量（`12.0`）。

**陷阱 2 —— 常量被借道 xmm 中转。** 这条更隐蔽。GCC 会把循环不变量广播提到
循环外，当向量寄存器不够时，它用下面这种方式物化常量：

```
vmovsd       .LC0(%rip), %xmm10      <- KNC 没有 xmm
vbroadcastsd %xmm10, %zmm4           <- KNC 没有寄存器形式的广播
```

汇编器直接拒绝。它偏偏对两类常量走了这条路：**掩码运算**的操作数，以及多项式
系数——因为一条 FMA 只能有一个内存操作数，另一个必须待在寄存器里。

修法是干脆不用标量形式表达它们：每个常量都写成 **`.rodata` 里的 8 车道数组**
再整块加载：

```c
static const double NB_K[11][8] __attribute__((aligned(64))) = { ... };
#define NK(i) _mm512_load_pd(NB_K[i])
```

整宽加载变成 `vmovapd`，合法。共转换了 11 组常量（4 个阈值、4 个乘数、
3 个牛顿迭代常数、6 个多项式系数），非法的 `vmovsd`/`xmm` 产物归零。

这与 [N6](N6-t9-gemm-row-stride-padding_CN.md) 是同一个教训的另一副面孔：
**在这套工具链上，不要试图说服编译器，而要安排它生成的代码本身是可表达的。**
检查是机械的——反汇编数 `%xmm`/`%ymm`，不为零的话卡上跑不起来。

## 5. 规则

> 把数值内核移植到 KNC 之前，先问 ISA 手册：FP64 流水线到底有什么。这里没有
> 开方、没有除法、没有倒数、没有倒数平方根——只有 FMA、比较，以及
> `VGETEXPPD`/`VGETMANTPD`。正确舍入的 `1/sqrt` 仍然可达：把 `x = m·2^e` 拆开，
> `q^e` 用四步无分支掩码缩放（靠数值比较驱动，因为没有整数转换可用），
> `m^(-1/2)` 用 5 次极小极大多项式，再走两次牛顿迭代。
> 每 8 个值约 30 条向量指令，精度约 1 ulp。
